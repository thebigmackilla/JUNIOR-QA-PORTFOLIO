# Примеры тест-дизайна

Учебные примеры для формы записи. Границы и правила необходимо сверять с требованиями.

## 1. Классы эквивалентности: телефон

Предположим, требования допускают российский номер из 11 цифр, начинающийся с 7 или 8. Это допущение для упражнения, а не универсальное правило для всех продуктов.

| Класс | Пример | Ожидаемое поведение |
|---|---|---|
| Валидный: 11 цифр, начинается с 7 | 79123456789 | Принять |
| Валидный: 11 цифр, начинается с 8 | 89123456789 | Принять |
| Невалидный: 10 цифр | 9123456789 | Отклонить |
| Невалидный: 12 цифр | 879123456789 | Отклонить |
| Невалидный: буквы в номере | 79ABC456789 | Отклонить или обработать по требованиям |
| Пустое значение | пусто | Ошибка обязательного поля, если поле обязательно |

## 2. Анализ граничных значений (BVA): рабочие часы

Предположим, рабочий день длится с 09:00 до 18:00. Нужно уточнить, разрешено ли начало ровно в 18:00 и учитывается ли длительность услуги.

- 08:59 — до начала рабочего дня;
- 09:00 — граница начала;
- 09:01 — внутри рабочего времени;
- 17:59 — перед окончанием;
- 18:00 — граница окончания;
- 18:01 — после окончания.

Если услуга длится 60 минут, начало в 17:59 или 18:00 может быть недопустимо. Ожидаемый результат зависит от правил планирования, а не только от времени старта.

## 3. Таблица принятия решений: подтверждение записи

| Условия / правила | R1 | R2 | R3 | R4 |
|---|---:|---:|---:|---:|
| Услуга выбрана | Да | Да | Да | Да |
| Дата и время доступны | Да | Да | Нет | Да |
| Контактные данные валидны | Да | Нет | Да | Да |
| Подтверждать запись? | Да | Нет | Нет | Да, только после серверной проверки |
| Ожидаемый результат | Запись создана | Ошибка валидации | Время отклонено | Запись создаётся только если сервер подтвердил доступность |

R4 — дополнительный сценарий на проверку серверных бизнес-правил.

## 4. Тестирование переходов состояний

Возможные состояния записи:
1. **Черновик** — форма ещё не отправлена.
2. **Проверка** — данные отправлены и валидируются.
3. **Подтверждена** — сервер успешно создал запись.
4. **Ошибка** — данные не прошли проверку или запрос завершился ошибкой.

Примеры переходов:
- Черновик → Проверка: пользователь нажимает «Подтвердить».
- Проверка → Подтверждена: сервер успешно создаёт запись.
- Проверка → Ошибка: отсутствует обязательное поле или время недопустимо.
- Ошибка → Черновик: пользователь исправляет данные.
- Повторная отправка после подтверждения не должна создавать дубликат, если это запрещено требованиями.
